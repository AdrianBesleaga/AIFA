AI Atomic Feature Architecture

Build software as small, isolated, AI-implementable features. Each feature ships with a contract: input, output, capabilities, rules, and behavioral tests.

The question

Can an AI agent implement one feature without understanding the whole project?

AIFA moves hidden project knowledge into explicit architectural contracts. The task stays small because the context is packaged, bounded, and testable.

The model

One feature. One context. Narrow capabilities.

01

Ticket Contract

The work item defines the goal, inputs, outputs, rules, failure cases, and acceptance tests.

02

Atomic Feature

The implementation receives one context object and uses only declared capabilities.

03

Capability Runtime

The runtime owns infrastructure like persistence, permissions, queues, logging, and transactions.

04

Behavioral Tests

Tests verify what the feature does, so the implementation can evolve without breaking the contract.

The shift

From codebase archaeology to feature contracts.

Most systems make agents explore first and implement second. AIFA makes the architecture say what the feature may know and do before implementation begins.

Traditional

Feature -> Service -> Repository -> Database

AIFA

Feature -> Context Capability -> Runtime -> Infrastructure

The contract

The ticket becomes an interface for humans and AI agents.

A good AIFA ticket removes guesswork. It tells the agent what to build, which capabilities are available, which behavior matters, and when the work is done.

  • One responsibility
  • Explicit input and output
  • Declared capabilities
  • Known failure cases
  • Acceptance tests before implementation
# Feature: Archive Project

Goal:
Allow an authorized actor to archive one project.

Input:
- projectId: string

Output:
- projectId: string
- archived: boolean

Allowed capabilities:
- project.load
- project.save
- permission.check
- audit.record

Acceptance tests:
- Archives an active project
- Rejects unauthorized actors
- Returns not_found for missing projects

Principles

Designed for delegatable software work.

Atomic

Each feature is the smallest meaningful behavior that can be implemented and tested independently.

Explicit

Input, output, capabilities, and failure cases are declared before code is written.

Bounded

Features cannot reach into hidden infrastructure or global application state.

Verifiable

Behavioral tests act as the completion signal for humans and AI agents.
